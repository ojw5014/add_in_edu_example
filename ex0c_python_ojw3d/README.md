# ex0c. OMX 파이썬 실행기 — OpenJigWare 3D

작성일: 2026-08-20. **예제 버튼 → 파이썬 파일 로드(파일 하나 = 프로젝트 하나) → ▶ Run = `Ojw.CPython` 실행**하는 교육용 윈도우 프로그램.
환경·동작은 ex0(픽앤플레이스)과 동일: 원통 제품 3개·팔레트·그리기 판·펜 거치대. 파지는 제품/펜 굵기만큼만 쥔다.

## 사용 흐름

1. 예제 버튼: ①픽앤플레이스 ②팔레타이징(3개, for문) ③사각형(직선) ④사각형(베지어 코너)
2. **▶ Run** → `Ojw.CPython`(강의 'C#에 Python 넣기')이 파이썬을 실행 → 로봇이 3D에서 동작
   - 실행 중에는 Run 버튼이 **"실행 중..."으로 바뀌며 비활성** — 완료되면 다시 활성화
   - 파이썬의 `[py]` 로그는 시작 직후 한꺼번에 표시된다 (파이썬은 명령을 즉시 모두 출력하고, 로봇은 그 큐를 순서대로 실행)
3. 코드는 편집창에서 수정 후 바로 재실행 가능. **리셋 버튼 = 중지 겸 초기화**:
   실행 중에 누르면 남은 명령을 끊고(현재 동작까지만), 한 번 더 누르면 초기 상태로 복귀

## 구조 (2026-08-21 확정): 임베디드 파이썬이 이 창의 3D 를 직접 구동 — Python.Runtime

**Run 을 누르면 파이썬 코드가 실행기(C#)와 같은 프로세스 안에서 실행된다.**
새 창을 띄우지 않고, **화면에 떠 있는(STL 렌더 포함) 3D 객체를 그대로 건네받아** 직접 부린다:

```python
# 실행기가 제공하는 두 객체 (예제 상단 주석에 명시):
#   c3d   — 화면의 OpenJigWare 3D (Ojw.C3d 그대로)
#   scene — 실물 로봇 통신 전용, 정체는 라이브러리 Ojw.CScene_t (COjw_42_Sim2Real.cs). 잡기/놓기는 그리퍼 여닫기로 자동
c3d.SetData(11, 30.0)                # Set 계열 — 관절 구동 (화면 즉시 반영)
x, y, z = c3d.CalcF(0, -1, False)    # FK (out 인자는 튜플로 반환)
# 잡기/놓기 명령 없음 — 그리퍼를 닫으면(수평 12mm 이내) 자동으로 잡히고, 열면 놓인다
```

- C# 쪽 구현: pythonnet 의 **Python.Runtime 임베딩** — `PythonEngine.Initialize()` 후 워커
  스레드에서 `scope.Set("c3d", m_C3d.ToPython())` + `scope.Exec(코드)`. print 는 sys.stdout
  대체 객체(CPyLog)로 로그 창에 표시. 리셋 버튼 = `PythonEngine.Interrupt`(KeyboardInterrupt)
- **앱은 x64 필수**(임베드되는 python 3.10 이 x64). `lib\Python.Runtime.dll` 참조
- 파이썬 코드는 워커 스레드 — UI(33ms 렌더)는 계속 돈다. `time.sleep` 기반 순차 코드 가능

## 원칙: 모든 알고리즘은 OpenJigWare.dll 안에 (2026-08-21)

수직 툴 IK·시간 보간 모션이 라이브러리 함수다 (COjw_12_3D.cs 에 추가, DLL 재빌드):

| DLL 함수 | 역할 |
|---|---|
| **`Play(시간ms, 딜레이ms, ID,각도, ID,각도, ...)`** | 강의 Play 형식 — 관절 이동, 끝날 때까지 대기 (파이썬/워커 스레드용) |
| **`PlayXyz(시간ms, 딜레이ms, 수식, x, y, z, Rx, Ry, Rz, 손목ID, 위치관절3...)`** | 툴 자세 3축(도) 지정 TCP 이동 — Ry=90 이 수직 아래. 자세 불가 시 위치 전용 폴백 |
| **`PlayXyzPath(시간ms, 딜레이ms, 수식, 점배열[x,y,z...], Rx, Ry, Rz, 손목ID, [위치관절3])`** | **폴리라인 경로를 멈춤 없이 한 획으로** — 렌더 틱마다 경로 위 목표점을 전진시키며 웜스타트 IK. 직선은 끝점만 주면 됨(사이는 연속 보간). 그리기 등 선형 연속 동작용 — PlayXyz 를 잘게 반복하면 점마다 감속·정지·재가속(펌프질) |
| `CalcInv_Tool(수식, x, y, z, 피치, 손목ID, [위치관절3])` | 손목 분리 IK (피치 파라미터) — `CalcInv_VerticalTool` 은 90도 래퍼 |
| `CalcToolPitch(수식, 손목ID)` | 툴 피치 실측 (수평 0 / 수직 아래 +90) |
| `MoveJoints_Start/_IsMoving/_Stop`, `MoveTool_Start` | 비블로킹 모션 API (C# 앱용) |
| `MoveJoints_Step()` | 모션 한 스텝 — **렌더 틱(OjwDraw 직전)에서 호출** |

- 3축 자세(Rx=롤, Ry=피치, Rz=요)와 4축 팔의 제약: 피치는 손목(14)이 실현, 롤은 롤 관절(15)을
  `Play` 로 별도 제어, 요는 팔 구조상 위치에 종속
- **함정: PlayXyz 에 자세 생략 오버로드를 만들지 말 것** — pythonnet 이 정수 인자를 짧은
  오버로드로 잘못 결합(손목ID 자리에 Rx)해 조용히 실패한다 (실측 후 단일 시그니처로 확정)
- 예제 상단은 `import clr` → `clr.AddReference("OpenJigWare")` → `from OpenJigWare import Ojw`
  → `c3d = scene.c3d` — 오픈지그웨어 사용이 코드에 명시된다

- **떨림(부들부들)의 원인과 해법**: 파이썬 스레드가 SetData 로 직접 움직이면 렌더 틱과 비동기
  33ms 두 루프가 되어 위상 표류·부분 갱신 스냅숏으로 떨려 보인다. `MoveJoints_Step()` 을 렌더
  틱에서 부르면 관절 갱신과 그리기가 같은 순간이라 떨림이 없다. `MoveTool_Start` 의 IK 도
  Step 첫 호출(렌더 스레드)에서 풀리므로 스레드 간 FK 충돌이 원천 차단된다 (hold 불필요)
- 예제 파이썬은 알고리즘 없이 위 함수 호출 + 시퀀스만 (~60줄). ex1·ex3 실행 검증 완료
- 구버전 DLL 백업: `lib\OpenJigWare_backup_20260821.dll`

## 실물 로봇 연결 — 같은 코드로 실물이 움직인다 (sim2real)

- 각 예제 상단의 주석 두 줄(`open(4, 1000000)` / `torqon()`)만 해제하면, **같은 파이썬 코드로
  3D와 실물 OMX Follower가 동시에 움직인다** (이후 모든 move/home/grip 이 실물에도 40Hz 스트리밍)
- `torqon()`은 켜기 전에 실물 자세를 읽어 3D를 먼저 맞춘다 → 토크 ON 순간의 점프 없음
- 관절 방향이 실물과 반대면 MainForm.cs 의 `REAL_SIGN` 배열에서 해당 관절만 -1 로 (현장 보정)
- **검증 (2026-08-20)**: 실물 OMX Follower(COM4, XL-430×6, 1Mbps)로 예제 1 픽앤플레이스 전체
  완주 — 접힘 자세에서 토크 ON(무점프) → 전 구간 추종 → 최종 홈 각도 실측 일치(±3도)
- 통신 함정(재현용): **쓰기/통신 직후의 첫 읽기는 스테일**(맵에 이전 값) — SyncRead 는 라이브러리
  `CSim2Real.ReadAll`(정착 재시도)로, 토크는 쓰고 100ms 후 재읽기로 실측 확인. 없는 포트로 Open 하면
  라이브러리가 에러 덤프를 쏟아내므로 `SerialPort.GetPortNames()`로 사전 확인

## 동작 구조

```
예제 py (진짜 python.exe — Ojw.CPython이 실행, PATH에 python 필요)
  └ 명령 함수 호출 → 명령 출력 → C#이 실시간 수집(GetResult) → 큐 → 순차 구동
    FK = m_C3d.CalcF(수식0) — 라이브러리

         ②손목각 θ14는 FK에서 툴 방향을 실측해 '수직까지 부족한 회전량'으로 직접 계산
         → 펜/그리퍼가 항상 수직 하향 자세 유지. 도달 불가 지점만 위치 전용 CalcInv 폴백

    — UI 스레드에서 기다리는 코드(Sleep/DoEvents/CTimer.Wait)가 전혀 없는 비블로킹 구조
```

## 주의 (재현용)

- **python이 PATH에 있어야 한다** — Run 전에 사전 확인하고 없으면 에러 표시 (없는 채로 CPython.Run을 부르면 내부 스레드가 멈춰 이후 Run이 전부 무시됨)
- CPython은 임시 py를 현재 작업 폴더에 생성 → 시작 시 `Directory.SetCurrentDirectory(StartupPath)` 필수
- 한글 출력: 파이썬 UTF-8 ↔ .NET cp949 불일치 대비 — C# 시작 시 `PYTHONIOENCODING=cp949:replace`
  환경변수 설정으로 해결 (자식 python 이 상속. 파이썬 코드 쪽 처리 불필요)
- 라이브러리가 파이썬 원문 출력을 에코하므로 `SetTextBox(숨김 텍스트박스)`로 흡수하고 표시할 것만 선별.
  명령이 하나도 수집되지 않으면 원문(stderr 포함)을 로그에 덤프해 오류를 표면화
- **Run마다 `new Ojw.CPython()`으로 인스턴스 교체** — 라이브러리 `Run()`은 내부 스레드 래치(m_nThread)가
  남아 있으면 아무 표시 없이 return하고, 결과 리스트도 재사용되면 이전 실행 출력이 이월될 수 있다.
  새 인스턴스가 이 두 침묵 실패 경로를 모두 차단 (연속 Run·예제 전환 검증 완료)
- **숨김 텍스트박스는 UI 스레드에서 핸들을 선생성**(`MainForm_Load`의 `.Handle` 접근) — 폼 밖 컨트롤은
  핸들이 없어 `InvokeRequired`가 false → CPython 작업 스레드가 UI를 직접 만지게 되는데,
  이는 **VS 디버거(F5)에서만** 크로스 스레드 검사에 걸려 무동작/멈춤이 된다 (직접 실행은 정상이라 헷갈림)
- **UI 스레드에서 DoEvents 계열로 기다리지 말 것** (F5 무한 대기의 진짜 원인) — 타이머 틱이 도는 앱에서
  DoEvents(CTimer.Wait 내부 포함)로 대기하면 틱 안에서 또 틱이 펌핑되고, 한 틱 처리가 틱 주기(33ms)를
  넘는 순간(디버거 부착 등으로 느려질 때) 재진입이 계속 쌓여 최상위 DoEvents가 영원히 못 돌아온다.
  모션은 반드시 StartMove(시작만) → 틱의 StepMotion(진행) 방식으로 — 이 구조엔 대기 코드가 없다
- **라이브러리 CalcInv 는 위치 전용** — `CalcInv_SetIKAlgorithm(5)` 를 넣어도 CalcInv 경로는
  0(CCD)/1(FABRIK) 분기뿐이라 CCD 로 동작한다(TRAC 은 마우스 드래그 IK 쪽 타입 번호). 자세(펜 수직)가
  필요하면 손목 분리 IK(SolveIkPen)를 쓸 것. 또 하나: **`CalcF(수식0, 15)` 는 TCP 와 같은 값을 반환**해
  툴 방향 측정엔 못 쓴다 — 방향은 'TCP − CalcF(수식0, 14)' 벡터로 잴 것 (실측으로 확인한 함정)
- 동작 중 창을 닫으면 FormClosing 이 3D를 해제한 뒤에도 PlayMove 루프가 돌 수 있다 —
  `m_bClosing` 플래그 + SetJoint/TcpPos/MoveTo 의 null 가드로 클린 종료 (ExitCode 0 검증)
- 빌드: `MSBuild OmxPythonRunner.csproj -t:Restore,Build -p:Configuration=Release` (net48 x86)
- **pythonnet 함정 4건 (재현용)**:
  ① `from OpenJigWare import Ojw` 는 전체 타입을 열거한다 — 의존 어셈블리(MyoSharp·AForge·
     OpenCvSharp 등)가 폴더에 없으면 ModuleNotFoundError. 의존 DLL 84종을 lib·bin 에 동봉함
  ② stl 경로는 반드시 상대경로(`SetAseFile_Path("stl")`) — 절대경로면 내부 경로 결합에서
     NotSupportedException

     STL 로드에서 무한 멈춤
